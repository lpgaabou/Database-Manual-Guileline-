# ClickHouse 一键安装部署说明

> 配套脚本：`cluster_deploy.sh`（集群一键编排，推荐）、`clickhouse_install.sh`（ClickHouse 节点）、`zookeeper_install.sh`（ZooKeeper 节点）
> 适用系统：CentOS 7 / RHEL 7（x86_64），以 **root** 运行
> 安装方式：官网离线 tgz 包（ClickHouse 20.11.4.13 + ZooKeeper 3.6.2 + JDK 1.8.0_261）
> 快速开始：生产集群直接看【第五章 集群一键并发部署】；单机测试看【第三章 单机一键安装】

---

## 一、架构方案选型（官网第二章）

| 方案 | 组成 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 方案1 纯分片 | MergeTree + Distributed | 架构简单、并行查询快 | 分片节点宕机后数据丢失、查询报错 | 测试/非核心数据 |
| 方案2 分片+副本复制 | MergeTree + Distributed（每分片2副本） | 数据有备份、节点故障不影响查询 | 分片存储损坏时**存量数据无法恢复**；Distributed 组件可能故障 | 过渡方案 |
| **方案3 分片+副本+高可用（生产推荐）** | **ReplicatedMergeTree + Distributed + ZooKeeper** | 数据安全、自动选副本、节点/单机柜故障不影响读写 | 写入走 ZK 协调，INSERT 延迟略长（仍可保证每秒数百次插入） | **生产环境** |

生产环境要点（官网总结）：
- 副本数至少 2 个（即 2 份数据）；建议跨机柜/跨主机部署。
- **写本地表、读分布式表**；批量写入（建议每批 1000~10000 行以上），避免大量小批触发频繁 merge。
- 并发查询数十到 100 左右；一台主机不建议多实例（CPU 能跑满时收益低）。
- ZooKeeper 独立 3~5 节点；一个业务对应一个集群，单集群节点不宜过多。
- 硬件参考：CPU 48 核、内存 128G/192G、磁盘 SSD RAID5/10、数据盘 1TB~40TB。

### 生产架构分层

```
        客户端 / 应用
             |
        chproxy 负载层（负载均衡 / 并发控制 / 用户映射，端口 9090，建议 2+ 节点）
             |
   -------------------------
   |   ClickHouse 集群      |   分片1: 节点A(主)+节点B(副本)
   |   ReplicatedMergeTree |   分片2: 节点C(主)+节点D(副本)
   |   + Distributed       |   分片3: 节点E(主)+节点F(副本)
   -------------------------
             |
      ZooKeeper 集群（3~5 节点，客户端端口 32181）
```

## 三、单机一键安装（最简单）

```bash
# 1. 把 4 个 tgz 放到 /clickhouse/soft/
#    clickhouse-common-static-20.11.4.13.tgz
#    clickhouse-common-static-dbg-20.11.4.13.tgz
#    clickhouse-server-20.11.4.13.tgz
#    clickhouse-client-20.11.4.13.tgz
mkdir -p /clickhouse/soft

# 2. 上传脚本并赋权
chmod +x clickhouse_install.sh

# 3. 一键安装（自动完成：hosts、用户、目录、limits/sysctl、SELinux/防火墙/THP、
#    解包 doinst、配置收敛、systemd 服务、启动校验）
./clickhouse_install.sh install

# 4. 登录验证
clickhouse-client -h 127.0.0.1 --port 9000 --user default
SELECT version();
```

### 多实例（同机再跑一个 9200 实例）

```bash
MULTI_INSTANCE=true ./clickhouse_install.sh install
clickhouse-client -h 127.0.0.1 --port 9200 --user default
```
关闭多实例（数据保留）：`MULTI_INSTANCE=false ./clickhouse_install.sh install`

## 四、生产集群手动分步部署（理解原理用）

> 生产环境**不需要**逐台执行下面的步骤，直接看【第五章 集群一键并发部署】。
> 本章保留手动流程，便于理解每个角色的安装内容。

集群规划（官网环境）：

| 主机 | IP | 角色 |
|---|---|---|
| xxx81 | 192.168.1.81 | 分片1 副本1 / ZK myid=1 |
| xxx82 | 192.168.1.82 | 分片1 副本2 / ZK myid=2 |
| xxx83 | 192.168.1.83 | 分片2 副本1 / ZK myid=3 |
| xxx84 | 192.168.1.84 | 分片2 副本2 / ZK myid=4 |
| xxx85 | 192.168.1.85 | 分片3 副本1 / ZK myid=5 |
| xxx86 | 192.168.1.86 | 分片3 副本2 |

### 第 1 步：所有节点配置主机名解析与基础环境

脚本默认会把上面的 hosts 规划幂等写入 `/etc/hosts`（不需要可清空脚本顶部 `HOSTS_ENTRIES`）。

### 第 2 步：在 81~85 安装 ZooKeeper（每台 myid 不同）

> **关键前提**：脚本内置的节点 IP 必须与本机真实网卡 IP 一致——ZK 启动时要把
> 仲裁/选举端口绑定到 `server.<myid>` 声明的 IP 上，IP 不在本机会导致服务启动即退出。
> 脚本已内置该校验，IP 不匹配会直接报错并给出提示。实际 IP 与内置规划不同时，
> 用 `ZK_NODES_LIST` 按真实 IP 注入（顺序即 myid=1..N）。

```bash
# 把 jdk-8u261-linux-x64.tar.gz、apache-zookeeper-3.6.2.tar.gz 放到 /clickhouse/soft/
chmod +x zookeeper_install.sh

# 实际网段与内置规划一致时：
./zookeeper_install.sh 1 install    # 在 81 执行
./zookeeper_install.sh 2 install    # 在 82 执行
./zookeeper_install.sh 3 install    # 在 83 执行
./zookeeper_install.sh 4 install    # 在 84 执行
./zookeeper_install.sh 5 install    # 在 85 执行

# 实际网段不同（例如 192.168.221.x 三台），每台都按真实 IP 注入：
ZK_NODES_LIST='192.168.221.129,192.168.221.130,192.168.221.131' ./zookeeper_install.sh 1 install
# 单机先验证一台：ZK_NODES_LIST 只填本机 IP，将以单机模式选举
ZK_NODES_LIST='192.168.221.129' ./zookeeper_install.sh 1 install

# 客户端端口默认 32181（可用 CLIENT_PORT=xxxx 覆盖；内部端口 ZK_PEER_PORT/ZK_ELECT_PORT 可改）
# 检查：systemctl status zookeeper；echo ruok 探测；Quorum 满足后自动选举 leader
echo ruok | nc 127.0.0.1 32181     # 返回 imok 即正常
```

### 第 3 步：在 81~86 安装 ClickHouse 并生成集群配置

每台节点执行安装时，**必须传入本节点对应的 shard / replica 宏**（对照下表）：

| 节点 | LOCAL_SHARD | LOCAL_REPLICA |
|---|---|---|
| 81 | 01 | xxcluster3s2r02_01_01 |
| 82 | 01 | xxcluster3s2r02_01_02 |
| 83 | 02 | xxcluster3s2r02_02_01 |
| 84 | 02 | xxcluster3s2r02_02_02 |
| 85 | 03 | xxcluster3s2r02_03_01 |
| 86 | 03 | xxcluster3s2r02_03_02 |

```bash
# 以 81 为例（其余节点替换 LOCAL_SHARD / LOCAL_REPLICA）
SETUP_CLUSTER=true \
LOCAL_SHARD=01 LOCAL_REPLICA=xxcluster3s2r02_01_01 \
./clickhouse_install.sh install
```

### 第 4 步：验证集群

```sql
-- 任一节点
SELECT * FROM system.clusters;

CREATE DATABASE xxxdb ON CLUSTER xxcluster3s2r02;

-- 复制表（本地表，ZK 自动同步副本）
CREATE TABLE xxxdb.ontime_local ON CLUSTER xxcluster3s2r02 (
    id Int32, name String, create_date Date
) ENGINE = ReplicatedReplacingMergeTree(
        '/clickhouse/tables/{layer}-{shard}/ontime_local', '{replica}')
PARTITION BY toYYYYMM(create_date)
ORDER BY (create_date, intHash32(id));

-- 分布式表（逻辑表，不存数据）
CREATE TABLE xxxdb.ontime_all ON CLUSTER xxcluster3s2r02 AS xxxdb.ontime_local
ENGINE = Distributed(xxcluster3s2r02, xxxdb, ontime_local, rand());

-- 写本地表 / 写分布式表均可；读分布式表
INSERT INTO xxxdb.ontime_local VALUES (1,'xxx','2020-12-01');
SELECT count(*) FROM xxxdb.ontime_all;
```

### 第 5 步（可选）：chproxy 负载分发

官网 3.9 节：在 2+ 节点部署 chproxy（端口 9090），配置 `replica-write / distributed-write / distributed-read` 三类用户与集群映射，实现负载均衡、并发控制。配置模板见官网 `chproxy` 目录与知识地图“负载分发”章节。

## 五、集群一键并发部署（推荐，支持几百台规模）

配套文件：

| 文件 | 作用 |
|---|---|
| `cluster_deploy.sh` | 集群编排脚本（在任意一台机器执行一次即可） |
| `cluster_hosts.conf` | 集群主机清单（主机名、IP、ZK编号、分片号、副本号） |
| `clickhouse_install.sh` | ClickHouse 单机安装脚本（由编排脚本自动下发调用） |
| `zookeeper_install.sh` | ZooKeeper 单机安装脚本（由编排脚本自动下发调用） |

### 执行效果

在集群内**任意一台机器**执行一次 `cluster_deploy.sh`，脚本自动完成：

1. **SSH 免密引导**：自动生成编排专用密钥并分发到所有节点（首次可用 `SSH_PASSWORD` 提供一次口令，自动安装 sshpass）；
2. **安装文件并发分发**：离线包与单机脚本按 sha256 校验，只推送有差异的节点（无 rsync 依赖，tar-over-ssh 增量收敛）；
3. **先并发部署 ZooKeeper**：按清单自动分配 myid，等待多数节点 `imok` 完成选举；
4. **再并发部署 ClickHouse**：按清单自动推导每台节点的分片/副本宏、ZK 地址、分片拓扑，生成集群配置；
5. **集群级校验**：逐节点校验 + 查询 `system.clusters` 成员数是否与清单一致；
6. **任一节点失败**：立即停止调度，按反向顺序（先 ClickHouse 后 ZooKeeper）对本次触及节点**自动远程回滚**。

### 第 1 步：规划主机清单

编辑 `cluster_hosts.conf`，每行一台机器，格式：

```
主机名|IP地址|ZK编号|分片号|副本号
```

- ZK编号：ZooKeeper 的 myid（从 1 开始），`0` = 不部署 ZK；
- 分片号：ClickHouse 分片编号，`0` = 不部署 ClickHouse；
- 副本号：分片中的副本编号（每分片 2 个副本填 1、2）。

默认 6 节点规划（3 分片 x 2 副本，ZK 复用前 5 台）：

```
xxx81|192.168.1.81|1|1|1
xxx82|192.168.1.82|2|1|2
xxx83|192.168.1.83|3|2|1
xxx84|192.168.1.84|4|2|2
xxx85|192.168.1.85|5|3|1
xxx86|192.168.1.86|0|3|2
```

**扩容到几百台**：按相同格式继续加行即可，分片/副本拓扑由脚本自动推导，无需改脚本。
ZK 建议独立 3~5 个奇数节点；每分片固定 2 个副本（脚本会对偶数 ZK、副本数不足给出告警）。

> **IP 必须真实**：清单里的 IP 必须是对应主机网卡上真实存在的地址，否则 ZK 无法绑定、
> 服务启动即退出（脚本会在安装前逐台校验并直接报错，不会再傻等端口）。
> 例如实验环境是 192.168.221.129~131 三台，就把清单改成这三个 IP。

**端口约定**：ZK 客户端端口默认 `32181`（ClickHouse 连此端口），内部仲裁 `2888`、
选举 `3888`；需要改时执行 `ZK_CLIENT_PORT=xxxx ZK_PEER_PORT=xxxx ZK_ELECT_PORT=xxxx ./cluster_deploy.sh deploy`。

### 第 2 步：放置离线包（只需在执行编排的这台机器上放一次）

把 6 个安装包放到 `/clickhouse/soft/`：

```
clickhouse-common-static-20.11.4.13.tgz
clickhouse-common-static-dbg-20.11.4.13.tgz
clickhouse-server-20.11.4.13.tgz
clickhouse-client-20.11.4.13.tgz
jdk-8u261-linux-x64.tar.gz
apache-zookeeper-3.6.2.tar.gz
```

### 第 3 步：一键部署整个集群

```bash
# 若所有节点 root 口令一致且尚未免密，带一次口令（仅用于分发公钥，之后全部走密钥）
SSH_PASSWORD=xxx ./cluster_deploy.sh deploy

# 已经免密后，直接执行；可反复执行做状态收敛（幂等）
./cluster_deploy.sh deploy

# 机器很多时调大并发波次（默认 10）
PARALLEL=30 ./cluster_deploy.sh deploy

# 需要同时部署 9200 第二实例
MULTI_INSTANCE=true ./cluster_deploy.sh deploy
```

### 第 4 步：验证

```bash
./cluster_deploy.sh verify
# 或登录任一节点：
clickhouse-client -q "SELECT * FROM system.clusters WHERE cluster='xxcluster3s2r02'"
```

### 日志与状态

- 编排运行目录：`/var/lib/cluster-deploy/run-<时间戳>/`（`latest` 软链指向最近一次）；
- 每台节点独立日志：`run-<时间戳>/<主机名>.log`，失败时直接打开对应主机日志定位。

### 全集群运维动作（均为一次执行、全集群生效）

```bash
./cluster_deploy.sh status                 # 各节点服务状态
./cluster_deploy.sh start                  # 按 ZK → CH 顺序启动
./cluster_deploy.sh stop                   # 按 CH → ZK 顺序停止
./cluster_deploy.sh restart                # 重启（ZK 选举完成后再起 CH）
./cluster_deploy.sh rollback               # 全集群回滚最近一次部署（CH → ZK）
./cluster_deploy.sh uninstall              # 全集群卸载（保留数据）
./cluster_deploy.sh uninstall --purge      # 连数据/日志一起删除

./kafka_install.sh
./clear.sh
./zookeeper_install.sh cluster install 
```

### 扩容场景

新增节点装好系统、网络可达后：在 `cluster_hosts.conf` 追加新行（新分片继续编号，或为已有分片补副本），重新执行 `./cluster_deploy.sh deploy`——已部署节点校验一致会全部跳过，只对新节点做安装与集群配置收敛。

### 常见问题：ZooKeeper 启动失败 / 32181 连不上

脚本现在会在两个地方主动拦截并直接打印原因（systemd 状态 + journalctl 最近 50 行 + ZK 自身日志）：

1. **安装阶段**：`systemctl restart` 后主动确认服务进入 `active`，启动即崩溃会立刻失败并回滚，不会再反复探测端口；
2. **校验阶段**：30s 收不到 `imok` 时输出同样的诊断信息。

最常见原因与处理：

| 现象/日志特征 | 原因 | 处理 |
|---|---|---|
| `Cannot open channel to x.x.x.x`、`Cannot assign requested address`、绑定 2888/3888 失败 | 清单 IP 与本机网卡 IP 不一致 | 用真实 IP 改 `cluster_hosts.conf`（手动安装用 `ZK_NODES_LIST` 注入） |
| `NoRouteToHost`、连接超时 | 防火墙/网络不通 | 脚本会关闭 firewalld；云主机还需放行安全组 32181/2888/3888 |
| `Address already in use 8080` | ZK 自带 AdminServer 的 8080 被占用 | 停掉占用进程，或在 zoo.cfg 加 `admin.enableServer=false` 后重跑 |
| `myid file is missing` / 权限拒绝 | data 目录异常 | 执行 `./zookeeper_install.sh <myid> rollback` 后重新 install |

手工排查命令：

```bash
systemctl status zookeeper --no-pager -l
journalctl -u zookeeper -n 50 --no-pager
tail -n 100 /clickhouse/zookeeper/log/*.log
echo ruok | nc 127.0.0.1 32181      # imok 即正常（集群未选出 leader 前进程也会响应 imok）
```

## 六、幂等性是如何保证的

- **hosts**：逐行 `grep` 检查，已存在不重复追加。
- **用户/组**：`getent group` / `id -u` 判断存在性，已存在只收敛口令与属组。
- **目录**：`mkdir -p`，仅记录“本次新建”的目录。
- **limits / sysctl / rc.local**：用 `# >>> tag >>>` 标记块管理，每次先删旧块再写新块，结果恒定。
- **软件包**：检测 `/usr/bin/clickhouse` 的实际版本，版本一致则跳过解包与 `doinst`；`doinst.sh` 本身是“解包复制”，重复执行结果相同。
- **配置覆盖**：自定义项全部放在 `config.d/`、`users.d/` 下固定文件中（覆盖式写入），不手工改主配置。
- **systemd**：对 unit 文件与全部配置计算 sha256，**仅当配置变化或服务未运行时才重启**，避免无谓停机。

因此可以安全地反复执行 `./clickhouse_install.sh install` 做状态收敛。

## 七、失败回滚是如何实现的

- 脚本 `set -Eeuo pipefail`，并通过 `trap '...' ERR` 捕获任何步骤的失败（含管道中途失败）。
- 安装开始即建立备份目录 `/var/lib/clickhouse-installer/backup/<时间戳>/`：
  - 所有**被修改前的原文件**（hosts、limits、sysctl、rc.local、selinux、localtime、旧二进制等）先 `cp -a` 备份；
  - 所有**本次新建**的文件/目录/软链/用户/服务写入清单 `manifest.add`。
- 失败时按清单**倒序撤销**：停服务 → 删软链 → 目录迁移还原 → 删新增文件 → 恢复原文件备份 → 删用户 → daemon-reload。
- 手动回滚最近一次安装：`./clickhouse_install.sh rollback`
- 卸载：
  ```bash
  ./clickhouse_install.sh uninstall          # 保留数据目录
  ./clickhouse_install.sh uninstall --purge  # 连数据/日志一起删除
  ```
  ZooKeeper：`./zookeeper_install.sh 1 rollback` / `./zookeeper_install.sh 1 uninstall`

## 八、附：数据盘 LVM 与挂载（官网 3.1，脚本默认不自动执行）

LVM 会格式化整块磁盘，属于破坏性操作，请按实际环境手工执行后再跑安装脚本：

```bash
pvcreate /dev/sdb
vgcreate datavg /dev/sdb
lvcreate -n datalv -L 200000M datavg
mkfs.ext4 /dev/datavg/datalv
mkdir /clickhouse
# /etc/fstab 增加：
# /dev/datavg/datalv /clickhouse ext4 defaults,nobarrier,noatime 0 0
mount /clickhouse
```
